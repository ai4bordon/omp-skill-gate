# OMP Skill Gate

**Жёсткий надсмотрщик скиллов для [Oh My Pi (OMP)](https://github.com/can1357/oh-my-pi).** Расширение, которое физически не даёт агенту работать «от себя»: прежде чем читать файлы, искать, править код или вызывать MCP-инструменты, агент обязан открыть подходящий скилл или явно задекларировать, что скиллов для задачи нет.

[English version](README.en.md)
---

**A deterministic skill-enforcement gate for Oh My Pi (OMP).** An extension that makes it physically impossible for the agent to skip skills: before any read, search, edit, bash or MCP call, the agent must open a matching skill or explicitly declare that none applies.

---

## Зачем это нужно

Промптами и правилами («сначала определи скилл, потом работай») агенты пренебрегают. Модель читает правило, отвечает «конечно» и всё равно лезет делать задачу «от себя». Причин две:

1. **Декларация дешевле действия.** Написать «учту» ничего не стоит, а прочитать скилл и следовать ему — это токены и дисциплина. Модель выбирает дешёвый путь.
2. **Нет цены у нарушения.** Даже если модель забыла про скилл, ничего не происходит: ход проходит, файлы правятся, никто не замечает.

Skill Gate закрывает обе причины технически:

- **Нарушение становится невозможным.** Пока ход не «вымыт», гейт блокирует вызов инструмента и возвращает модели ошибку с инструкцией. Файл просто не запишется.
- **Нарушение становится видимым.** После каждого ответа агента в чат падает детерминированная сводка: какие скиллы применены, была ли декларация «скиллов нет», сколько было блоков. Без единого дополнительного вызова модели.

## Как это выглядит в сессии

```
Ты: сделай лендинг для кофейни

Агент: (пытается вызвать write)
✗ skill-gate: перед первым действием в этом ходе нужно одно из двух:
  (1) открыть профильный скилл через read skill://<имя> ...
  либо (2) явно написать в ответе строку «скиллов нет - причина».
  Сейчас и то, и другое отсутствует - действие заблокировано.

Агент: (читает skill://frontend-design)
Агент: ...работает по скиллу, правит файлы...

skill-gate: блоков: 1 · скиллы: frontend-design
```

Сводка после ответа (событие `agent_end`, один раз на запрос):

```
skill-gate: блоков: 0 · скиллы: frontend-design, design-taste-frontend
skill-gate: блоков: 1 · скиллов нет (тривиальная правка текста, скилла не требует)
skill-gate: блоков: 2 · без скилла и без декларации · ШТРАФ: ход не вымыт
```

## Как работает

Расширение на Extension API OMP: шесть хуков на события сессии, ноль вызовов модели. Всё состояние в замыкании фабрики, сессия локальна.

| Хук               | Что делает                                                                             |
| ----------------- | -------------------------------------------------------------------------------------- |
| `input`           | Новый запрос от пользователя: ход объявляется «грязным» (требует скилл или декларацию) |
| `tool_result`     | Успешное чтение `skill://<имя>`: запоминает имя скилла, вымывает ход                   |
| `message_update`  | Декларация «скиллов нет» в тексте ответа: вымывает ход, запоминает причину             |
| `tool_call`       | Пока ход грязный: блокирует гейтимые инструменты, возвращает модели reason             |
| `agent_end`       | Печатает сводку по скиллам и блокам (один раз на запрос)                               |
| `registerCommand` | Команда `/skill-gate`: статус гейта в любой момент                                     |

### Что гейтится

- Правки файлов: `edit`, `write`, `ast_edit`
- Чтение и разведка: `read`, `grep`, `glob`, `find`
- Исполнение: `bash`, `eval`
- Внешние действия: `web_search`, `task` (сабагенты), все `mcp__*`

### Что не гейтится

- `read skill://...` — открытие скилла, это и есть выход из блока (иначе петля)
- Внутренние URI OMP (`xd://`, `local://`, `mcp://`, `proc://`, `skill://` и др.) — механизмы самого агента, не файловая система
- Вся работа сабагентов (`ctx.agent.kind === "sub"`) — гейт действует только на главную сессию
- Если цель действия не распознаётся — блок (fail-closed)

### Как модель выходит из блока

Два пути, оба детерминированные:

1. **Открыть скилл**: `read skill://<имя>`. Гейт пропускает чтение скилла всегда, успешный `tool_result` вымывает ход.
2. **Задекларировать отказ**: написать в ответе строку вида «скиллов нет - причина». Регулярка ловит и русский, и английский вариант (`no skills`, `no applicable skills`...).

Дальше ход чист: все инструменты разблокированы до следующего запроса.

## Установка

Требования: OMP (oh-my-pi) 18.x, включённые скиллы в профиле (см. `skillful: true` в `config.yml`).

```bash
# В extensions-каталог твоего профиля
cp skill-gate.ts ~/.omp/profiles/<твой-профиль>/agent/extensions/skill-gate.ts
```

Гейт подхватится в **новой** сессии (расширения читаются на старте). Проверка:

```
/skill-gate
→ skill-gate: ход clean · blocked this turn: 0 · total: 0
```

### Настройка

Все параметры — константы в начале файла:

- `GATED_TOOLS` — список гейтимых инструментов. Убери `read`/`grep`/`glob`/`find`, если хочешь мягкий вариант «только правки и внешние действия».
- `MCP_PREFIX` — маска MCP-инструментов.
- `INTERNAL_SCHEME` — внутренние схемы OMP, которые не блокируются.
- `DECLARED_NO_SKILL` — регулярка декларации «скиллов нет».
- `BLOCK_REASON` — текст, который видит модель при блоке. Формулировка важна: от неё зависит, как охотно модель пользуется декларацией вместо чтения скилла.

## Ограничения

- **Гейт не выбирает скилл.** Выбор — задача модели (триггеры скиллов должны быть в промпте профиля). Гейт лишь делает «просто начать делать» невозможным.
- **Декларацию нельзя проверить.** Если модель пишет «скиллов нет», хотя подходящий скилл существует, гейт пропустит. Это предел детерминизма: гейт — стена, не читатель мыслей.
- **«Применён» = «открыт».** Сводка показывает, что файл скилла прочитан. Следовала ли модель его инструкциям — не знает никто.
- В json/RPC-режиме OMP сводка не выводится (уведомления TUI не дублируются в stdout). Полный цикл — в интерактивной сессии.
