> **Проблема:** агент открывает скилл, но работает мимо него. Или не открывает вовсе.
> **Промпты не лечат:** написанное правило ничего не стоит модели, нарушение ничем не наказывается.
> **Решение:** два слоя, один без модели, второй с дешёвой моделью.

## Как это выглядит вживую

```text
┌─ Слой 1 ───────────────────────────────────────────────┐
│ агент: лезет в код, скилл не открыт                     │
│ гейт:  ✋ BLOCKED — сначала read skill://<имя>           │
│         или строка «скиллов нет - причина»              │
├─ Слой 2 ───────────────────────────────────────────────┤
│ агент: скилл открыт, чек-лист извлечён (o1..o6)         │
│ гейт:  перед завершением — статус по каждому пункту     │
│         «сделано: [o4] — доказательство: <факт хода>»   │
│ гейт:  доказательство сверено с журналом? ✅ отпущено    │
│         выдумка или самоподтверждение? ✋ BLOCKED        │
└─────────────────────────────────────────────────────────┘
```

## Два слоя, две роли

| Слой | Исполнитель | Что держит | Как действует |
|:---|:---|:---|:---|
| **Гейт** | код расширения, без модели | форму: скилл открыт, статус по каждому пункту, доказательство из реального события хода | блокирует вызов инструмента |
| **Советник** | дешёвая модель-ревьюер | смысл: артефакт содержит то, что требует пункт скилла | замечание после хода, не блокирует |

Выбор скилла остаётся за агентом: гейт держит форму, Советник держит смысл, кто какой скилл применить - решает исполнитель.

## Результаты стенда

20 промптов × 18 доменов + 2 контрольных, три прохода. Подробности: [`bench/`](bench/).

| Метрика | Проход 1 | Проход 2 | Проход 3 |
|:---|:---|:---|:---|
| Выбор скилла | 20/20 верных | 20/20 | 8/8 перегнанных |
| Блоки гейта на прогон | ~2.5 | ~2 | 0-1 |
| Ходов на прогон (среднее) | 27 | 25 | **13** |
| Замечаний Советника | 30 (24 про шум) | 24 | **5** |
| Статусы принимаются | с 3-4 попытки | со 2-3 | **с первой** |

Побочный эффект: пропуск на повышение статуса виден по бенчмарку (требование v5.2 - снижение «повторов session-stop» → внедрено в v5.3, прогон 3 = с первой попытки).

## Быстрый старт

Требуется OMP с поддержкой расширений и Bun для проб.

```bash
# 1. расширение в профиль
cp src/skill-gate.ts ~/.omp/profiles/<ваш-профиль>/agent/extensions/

# 2. фоновые скиллы профиля (загружаются всегда - не считаются выбором)
echo '["имя-скилла"]' > ~/.omp/profiles/<ваш-профиль>/agent/extensions/skill-gate.background.json

# 3. пробы (bun, без сети и модели)
bun probes/obligations-test.ts   # 13/13
bun probes/quote-test.ts         # 3/3
bun probes/rx-fix-test.ts        # 9/9

# 4. посмотреть, какие ваши скиллы дают обязательства
bun probes/mass-check.ts ~/.omp/profiles/<ваш-профиль>/agent/skills
```

Новые сессии OMP подхватывают расширение при старте. Кейсы с локальными скиллами на чужой машине печатают «пропущено» и не падают.

## Границы системы

- Гейт проверяет форму, не содержание: «сделано: o4, доказательство: README.md» пройдёт даже при плохом README. Содержание держит Советник, а он вероятностный.
- Отчёт по обязательствам стоит один-два хода на задачу.
- Дорогие задачи дороги сами по себе, не из-за гейта: им нужен отдельный потолок итераций.
- Сабагенты (`task`) не покрыты: гейт следит только за main-агентом.

## О сверке контрольных сумм

Git на Windows при checkout конвертирует переводы строк (CRLF), md5 файла в клоне будет отличаться. Для побайтной сверки: `git show HEAD:src/skill-gate.ts | md5sum`.
