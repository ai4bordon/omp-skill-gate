# Skill Gate System

Полная система принудительного применения скиллов для [Oh My Pi (OMP)](https://github.com/can1357/oh-my-pi):
детерминированный гейт + смысловой ревьюер (Советник). Этот репозиторий содержит всю разработку:
исходники всех версий, спецификацию, пробы, стенд проверки на 20 промптах и инструкции Советника.

Проблема, которую решает система: агент **открывает** скилл, но **работает мимо него**. Или не открывает вовсе.
Промптами это не лечится: написанное правило ничего не стоит модели, а нарушение ничем не наказывается.
Система закрывает это технически, в два слоя:

| Слой | Кто | Что проверяет | Как |
|---|---|---|---|
| Гейт | код расширения, без модели | форму: скилл открыт, по каждому пункту статус, доказательство привязано к реальному событию хода | блокирует вызов инструмента |
| Советник | дешёвая модель-ревьюер | содержание: артефакт содержит то, что требует пункт скилла | замечание после хода, не блокирует |

## Состав репозитория

```
src/skill-gate.ts       текущая версия расширения (v5.2)
advisor/WATCHDOG.md     инструкция Советнику: роль, границы, лимит замечаний
advisor/WATCHDOG.yml    подключение к Советнику OMP
specs/                  спецификация: requirements.md, design.md, tasks.md
probes/                 пробы расширения (bun, без сети и модели)
bench/                  стенд: 20 промптов, 18 доменов + 2 контрольных, сводки трёх проходов
history/                README первой публичной версии (v1.0)
```

## Установка в свой профиль OMP

Требуется: OMP с поддержкой расширений (`~/.omp/profiles/<профиль>/agent/extensions/`) и Bun для проб.

1. Скопируйте расширение:

```bash
cp src/skill-gate.ts ~/.omp/profiles/<ваш-профиль>/agent/extensions/
```

2. Проверьте пробы (по желанию, но рекомендуется):

```bash
cd probes
bun obligations-test.ts   # 13/13: извлечение обязательств, статусы, доказательства, предохранитель
bun quote-test.ts         # 2/2: цитата из вывода инструмента принимается, выдуманная нет
bun rx-fix-test.ts        # 9/9: разбор строк статуса с маркерами списка и именем скилла
bun ref-check.ts          # 2/2: тело скилла несёт обязательства, references/ нет
```

3. Посмотрите, какие из ваших скиллов попадут под контроль обязательств:

```bash
bun probes/mass-check.ts ~/.omp/profiles/<ваш-профиль>/agent/skills
```

Скиллы с чек-листами (`- [ ]`) или нумерованными шагами (`1. …`) дают обязательства;
справочники без процедуры дают 0, и для них гейт работает только как входной шлагбаум.

4. Новые сессии OMP: расширения подхватываются при старте сессии.

## Как работает гейт

Слой 1 (v1.0): в ходе нельзя вызывать инструменты, пока не открыт скилл (`read skill://<имя>`)
или не написана строка «скиллов нет - причина». Нарушение физически невозможно: вызов блокируется.

Слой 2 (v5.x): при открытии скилла из его тела извлекаются обязательства (до 6 на скилл,
до 10 суммарно). Перед завершением хода агент обязан по каждому пункту дать строку:

```
- сделано: <имя-скилла> [o1] — доказательство: <путь, команда или цитата из вывода>
- неприменимо: <имя-скилла> [o2] — причина: <текст>
- не сделано: <имя-скилла> [o3] — причина: <текст>
```

Доказательство проверяется по журналу хода: путь должен существовать в фактах хода
(файл прочитан до правки или создан в ходе), команда должна была запускаться, цитата в кавычках
должна реально встречаться в выводе инструментов. Самоподтверждение закрыто: строка статуса
не может доказать сама себя. Честный пробел («не сделано») принимается: гейт не учит врать.
После трёх отказов срабатывает предохранитель, ход пропускается с пометкой «НЕ ПРИНЯТО».

## Как работает Советник

Советник OMP подключается флагом `--advisor`. Инструкция `advisor/WATCHDOG.md` задаёт ему роль
смыслового ревьюера: найти в транскрипте `read skill://…`, открыть скилл самому, выпиcать его
чек-лист, сверить с фактически сделанным и сказать только про материальные пробелы содержания.
Не больше двух замечаний, молчание при полном закрытии, никакого дублирования гейта и придирок к стилю.

Подключение: скопируйте `advisor/WATCHDOG.md` и `advisor/WATCHDOG.yml` в каталог профиля
(`~/.omp/profiles/<профиль>/agent/`) и запускайте omp с `--advisor`.

## Результаты проверки (стенд на 20 промптах)

Три прохода по одним и тем же 20 промптам (18 доменов + 2 контрольных). Подробности: `bench/`.

| Метрика | Проход 1 | Проход 2 | Проход 3 |
|---|---|---|---|
| Выбор скилла | 20/20 верных | 20/20 | 8/8 перегнанных |
| Блоки гейта на прогон | ~2.5 | ~2 | 0-1 |
| Ходов на прогон (среднее) | 27 | 25 | 13 |
| Замечаний Советника | 30 (24 про шум гейта) | 24 | 5 |
| Статусы принимаются | с 3-4 попытки | со 2-3 | с первой |

Замечание о цене: часть прогонов шла на deepseek-v4.1-flash-1017, часть на glm-5.3;
в сопоставимых тарифах стоимость прохода 2 и 3 одинакова (~$0.45-0.47 на 8 прогонов).

## Границы системы

- Гейт проверяет форму, не содержание: «сделано: o4, доказательство: README.md» проходит
  даже при плохом README. Содержание держит Советник, а он вероятностный.
- Отчёт по обязательствам стоит один-два хода на задачу.
- Дорогие задачи (лендинг с генерацией картинок, итеративный UI) дороги сами по себе,
  не из-за гейта: им нужен отдельный потолок итераций.

## О сверке контрольных сумм

Рабочая копия расширения на машине автора: md5 `0885e3e589aa90d3e47435fbeb30593c`
(v5.2, 27 466 байт). Git на Windows при checkout может конвертировать переводы строк
(CRLF), тогда md5 файла в клоне будет другим: `2470b4370cdaa01502fb42c4dc008900`.
Содержимое идентично; для побайтной сверки используйте
`git show HEAD:src/skill-gate.ts | md5sum`.
