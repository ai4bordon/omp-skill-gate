# Воспроизведение на другой машине

Цель: получить ту же систему на чистом компьютере: гейт, Советник, проверка пробами.

## Требования

- OMP (Oh My Pi) с поддержкой расширений и скиллов;
- профиль OMP с настроенной моделью (см. конфигурацию профиля);
- Bun (для проб) или любой Node-совместимый рантайм;
- API-ключ модели: нужен только для живых прогонов, не для проб.

## Шаг 1: гейт

```bash
cp src/skill-gate.ts ~/.omp/profiles/<ваш-профиль>/agent/extensions/
# фоновые скиллы профиля (загружаемые всегда), если есть:
echo '["имя-скилла"]' > ~/.omp/profiles/<ваш-профиль>/agent/extensions/skill-gate.background.json
```

Начните новую сессию OMP: расширения подхватываются при старте.

Проверка без модели и сети:

```bash
cd probes
bun obligations-test.ts   # 13/13 (на машине без каталога ~/.agents/skills: 11/11, кейсы 10-11 пропущены)
bun quote-test.ts         # 2/2
bun rx-fix-test.ts        # 9/9
bun ref-check.ts          # синтетика 2/2 + реальные скиллы, если установлены
```

Все пробы гоняют расширение через фейковый `pi`: события input, tool_call,
tool_result, message_update, session_stop. Никакой сети, никакой модели.
Кейсы с локальными скиллами (obligations 10-11, ref-check «code-review/spec-driven»)
проверяются только если скиллы установлены в `~/.agents/skills`, иначе печатается
«пропущено» и счётчик их не включает.

## Шаг 2: покрытие вашего каталога скиллов

```bash
bun probes/mass-check.ts ~/.omp/profiles/<ваш-профиль>/agent/skills
```

Вывод: какие скиллы несут обязательства (чек-листы, шаги) и сколько. Скиллы с 0:
справочники, для них гейт остаётся входным шлагбаумом. Это не поломка, а разделение:
справочник не описывает порядок работы, требовать статусов из него было бы шумом.

Эталонные числа с машины автора (профили три профиля автора): 40/78, 86/143, 56/65.

## Шаг 3: Советник

```bash
cp advisor/WATCHDOG.md advisor/WATCHDOG.yml ~/.omp/profiles/<ваш-профиль>/agent/
```

Запускайте omp с `--advisor`. Советник поднимется на модели из роли judge профиля.
Стоимость обзора на машине автора: $0.029 за прогон (6 запросов).

## Шаг 4: быстрая живая проверка

Одна задача в чистом каталоге:

```bash
mkdir /tmp/sg-check && cd /tmp/sg-check
echo 'export function add(a, b) { return a + b; }' > calc.js
omp -p --advisor "Добавь в calc.js функцию mul и покрой её тестом по TDD: сначала тест, потом код."
```

Ожидание: агент откроет скилл TDD (гейт не пустит без этого), напишет тест раньше кода,
запустит его, увидит падение, напишет код, увидит зелёный, в конце даст строки
«сделано: … — доказательство: …». Гейт примет статусы с первого раза.

## Шаг 5 (по желанию): полный стенд

```bash
cd bench
python seed.py
python run.py
python parse.py results
```

20 прогонов, около 2-4 часов на 5 воркерах, стоимость зависит от вашей модели
(на машине автора: ~$0.06 за средний прогон на дешёвой модели).

## Что взять из чужой машины, а что нет

| Артефакт | Переносится? |
|---|---|
| `src/skill-gate.ts` | да, это и есть система |
| `advisor/WATCHDOG.md` + `.yml` | да, но модель в yml это конфиг вашей машины |
| `probes/` | да, без сети |
| `bench/` | да, но результаты будут вашими: модель и каталог скиллов отличаются |
| `specs/` | для чтения: требования и дизайн-решения |

Сводки стенда (`bench/results/`) включены как свидетельство работы системы на машине
автора; ваши цифры будут другими, и это нормально.

## Траблшутинг

| Симптом | Причина | Лечение |
|---|---|---|
| гейт блокирует всё, включая чтение скиллов | старая версия (< 3.2) | обновить `src/skill-gate.ts` |
| статусы не признаются | форма строки: маркер допустим, но тире после двоеточия обязательно | см. docs/gate.md, форма статуса |
| гейт требует статусы от справочника | версия < 5.2 (references-дыра) | обновить до v5.2 |
| три отказа подряд, потом «НЕ ПРИНЯТО» | агент не понял форму | предохранитель сработал; подсказка в reason блока |
| Советник молчит | всё закрыто (правильно) либо модель роли judge не настроена | проверить конфиг профиля |
