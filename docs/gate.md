# Гейт: устройство и контракт

Детерминированное ядро системы. Файл: `src/skill-gate.ts` (v5.2, md5 `0885e3e589aa90d3e47435fbeb30593c`).
Спецификация: `specs/requirements.md` (R1-R8.6), `specs/design.md` (D1-D11).

## События OMP, на которых стоит гейт

| Событие | Что делает гейт |
|---|---|
| `input` | сброс состояния хода |
| `tool_call` | слой 1: блокировка, если скилл не открыт и нет декларации |
| `tool_result` | чтение `skill://`: разбор тела, извлечение обязательств, подсказка агенту; остальные результаты идут в накопитель выводов для проверки цитат |
| `message_update` | разбор строк статуса из ответа агента |
| `session_stop` | слой 2: блок завершения хода, если обязательства не закрыты или без подтверждения |
| `agent_end` | сводка в чат: блоки, скиллы, статусы, доказательства (notification-only) |

## Слой 1: входной шлагбаум

До первого gated-инструмента (edit, write, ast_edit, read, grep, glob, find, bash, eval,
web_search, task, все `mcp__*`) в ходе должно быть одно из двух:

1. `read skill://<имя>` (само чтение скиллов не блокируется, иначе невозможно выполнить требование);
2. строка в ответе: «скиллов нет - причина».

Внутренние схемы (`xd://`, `local://`, `agent://`, `skill://` и прочие) не считаются
действием: правки по ним это работа системы, а не пользовательской задачи.

Фоновые скиллы (`BACKGROUND_SKILLS` в конфиге) не вымывают ход: они загружаются всегда
по инструкции профиля, поэтому их открытие не выбор агента. Ход «вымыт» только
профильным скиллом или декларацией. Иначе профиль с обязательным фоновым скиллом
терял бы защиту слоя 1 целиком.

## Слой 2: обязательства

Извлечение из тела SKILL.md (`extractObligations`):

- чек-лист: `- [ ] пункт` в любом месте файла;
- шаги: нумерованные строки `1. …` и нумерованные заголовки `### 1. …`;
- секционные шаги весомее случайных: строка из секции с заголовком
  (process / workflow / steps / шаги / чек-лист / алгоритм / процедура) попадает
  в scopedSteps, прочие в looseSteps;
- код-блоки пропускаются: там примеры, а не требования;
- выбор: чек-лист при >= 2 пунктах, иначе scoped, иначе scoped + loose;
- потолки: 6 на скилл, 10 суммарно; дедупликация; стабильные id `o1..o6`;
- только тело скилла: `isSkillBody = /^skill:\/\/[^/?#]+(?:[/\\]SKILL\.md)?$/i`,
  `references/` обязательств не порождает.

Строки статуса, которые обязан дать агент (`STATUS_LINE`):

```
- сделано: <имя-скилла> [o1] — доказательство: <путь, команда или цитата>
- неприменимо: <имя-скилла> [o2] — причина: <текст>
- не сделано: <имя-скилла> [o3] — причина: <текст>
```

Маркер списка (`- `, `* `, `+ `) допускается. Тире после id - часть формата строки
(агент копирует форму из подсказки гейта), в свободном тексте документов используется дефис. Имя скилла опционально, но нужно при
нескольких открытых скиллах: id `o1..o6` у них совпадают, ключ различается именем.

Проверка доказательств (`classifyEvidence`):

| Вид | Условие | Значение |
|---|---|---|
| external | файл прочитан в ходе ДО своей записи, или файл существовал до хода | сильное |
| self | файл записан в ходе и не читался | подтверждает существование |
| quote | фрагмент в кавычках (`` ` `` « " ) >= 8 символов реально есть в накопленных выводах инструментов или в ответе вне строк статуса | сильное |
| none | ничего не найдено | блок |

Самоподтверждение закрыто: строки статуса вычитаются из текста, по которому ищется цитата.
Цитата из собственной формулировки агента, не встречавшейся в выводах инструментов,
не принимается.

Накопитель выводов: content-тексты из `tool_result`, потолок 400 000 символов, срез
8000 на вызов (чтобы длинный вывод не разрос память).

## Защита от ложных блоков

- Ход-справка (только чтение скиллов, без gated-действий) не требует статусов.
- Честный пробел «не сделано» принимается и виден в сводке.
- Предохранитель: 3 отказа `session_stop` → карточка «НЕ ПРИНЯТО» в сводке, дальше
  ход пропускается.
- Скилл-справочник без обязательств не порождает пустых требований.

## Форма подсказки агенту

При открытии скилла агент получает `additionalContext` с перечнем обязательств
(`[o1] текст · [o2] текст · …`) и живым примером строки статуса с именем этого скилла.
При блоке `session_stop` в reason уходит полный список: «без статуса: …» и
«статус „сделано“ без подтверждения в журнале: …».

## Команды

`/skill-gate` - статус: открытые скиллы, обязательства, счётчики доказательств,
блоков за ход.

## Границы контракта (D9 из спеки)

Гейт проверяет привязку, не содержание: «существует ли доказательство в журнале хода»,
а не «хорош ли артефакт». Содержание это зона Советника (`docs/advisor.md`).
Это не недоделка, это граница детерминизма: код может проверить существование,
но не качество.
